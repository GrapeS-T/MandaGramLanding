# MandaGramLanding — инструкции для агентов

Статический сайт mandagram.com: Astro 4 и TypeScript; главные страницы RU/EN, русскоязычная база знаний, SDK и примеры нативных плагинов. Это не репозиторий Telegram-клиента и не серверный API.

## Всегда

- Сохраняй посторонние изменения; меняй только необходимое. При смене контракта обновляй вызовы и документацию, удаляй ставший ненужным код. Не редактируй результат сборки в `dist/` вместо исходников.
- `README.md` — краткое знакомство с проектом для обычного читателя: что это, для кого и полезные ссылки. Не добавляй туда сложные технические сведения, команды, устройство проекта, инструкции по разработке и публикации или подробное описание функций приложения. Всё это размещай в профильных документах `docs/`; в README оставляй только короткие ссылки. При переносе документации сохраняй сведения и обновляй ссылки, не поддерживай дублирующие описания.
- Не коммить ключи, токены, сессии, базы и личные логи. Checkout клиента используй для сверки реализации; не меняй данные работающего клиента и не включай их в SDK или сайт.
- Разработка — в рабочих ветках от `dev`; в `dev` только merge, в `main` только PR из `dev`. Перед правкой и Git-операциями читай [docs/git.md](docs/git.md): ветки и коммиты. Файл скопирован из клиента: его Gradle-команды, правила клиентских пакетов и ссылки на отсутствующие здесь документы сборки не описывают сборку сайта.
- Production публикуется только из `release`; push в неё запускает деплой. Не разрабатывай в `release` и не публикуй сайт без поручения. Принятое состояние `main` переносится в `release` через fast-forward по [docs/deployment.md](docs/deployment.md); при расхождении истории не используй force push. Локальная сборка не является публикацией.
- Переиспользуй существующих владельцев контента в `src/data/`, общие компоненты и макеты. При общих изменениях главной сохраняй согласованность RU/EN. Ресурсы с публичным URL размещай в `public/`; файлы из `src/assets/` используй через импорт.
- Источник истины для возможностей клиента и Plugin API — реализация соответствующей ревизии MandaGram. Не обещай релизы, UI-функции, безопасность или совместимость по одному комментарию, enum или старому примеру. Нативные плагины не изолированы песочницей; SDK и клиент должны соответствовать друг другу.
- Статьи редактируй в `src/data/articles/`: сохраняй slug и HTML-якоря, новые статьи добавляй в порядок категорий `src/data/kb.ts` и `public/sitemap.xml`. `content` — доверенный HTML, не Markdown; экранируй код и TypeScript template strings. Оглавление и поисковый индекс вычисляются: не создавай их ручные копии, в том числе `public/kb/search.json`.
- Не меняй ABI независимо от клиента. Канонические headers — `public/include/`, ревизия и SHA256 — `scripts/plugin-sdk-source.json`; `public/examples/include/` и архив SDK генерируются. Не правь производные копии отдельно и не обновляй hashes только ради прохождения проверки. При смене SDK сверяй реализацию, обновляй bindings, примеры и статьи вместе.
- Проверяй изменённый сценарий; сообщай только выполненные проверки и ограничения. Для UI проверяй реальную страницу на широком и узком экране, обе темы, клавиатурную навигацию и изменённые взаимодействия. Сборка не доказывает работу поиска, диалогов или загрузку плагина в клиент.

## Читать по задаче, до правки

- [README.md](README.md) — краткая информация о проекте для обычного читателя, не техническое руководство.
- [docs/development.md](docs/development.md) — локальный запуск, карта исходников, поведение сайта и добавление участников.
- [docs/content.md](docs/content.md) — обновление статей, сверка реализации клиента, SDK и проверки примеров.
- [package.json](package.json) и [astro.config.mjs](astro.config.mjs) — доступные команды, зависимости и маршрутизация. Node.js 22, установка через `npm ci`; разработка — `npm run dev -- --host 127.0.0.1`, сборка — `npm run build`, проверка результата из `dist/` — `npm run preview -- --host 127.0.0.1`. Отдельной команды тестов нет.
- Для документации клиента — соответствующий checkout MandaGram: `docs/development.md`, профильные `docs/architecture/`, `src/native/include/mandagram_plugin.h` и реализация в `src/main/kotlin/com/mandagram/plugin/`. Пути и порядок сверки описаны в [docs/content.md](docs/content.md); не подменяй недоступную проверку предположением.
- Для SDK и примеров — [scripts/SDK-BUILDING.txt](scripts/SDK-BUILDING.txt), [scripts/plugin-sdk-source.json](scripts/plugin-sdk-source.json) и [.github/workflows/plugin-examples.yml](.github/workflows/plugin-examples.yml). `npm run sdk:verify-source -- <путь-к-MandaGram>` сверяет источник; сборка сайта упаковывает SDK, но не компилирует плагины и не запускает клиент.
- Для публикации — [docs/deployment.md](docs/deployment.md), [.github/workflows/deploy.yml](.github/workflows/deploy.yml), [deploy/receive.sh](deploy/receive.sh) и [deploy/Caddyfile](deploy/Caddyfile). Проверка production и операции на сервере — отдельная часть поручения, не автоматическое завершение правки.

Этот файл и профильная документация — действующие правила. При конфликте правил проекта приоритет у `AGENTS.md`; версии, команды и автоматизацию сверяй с конфигурацией и workflows. Не дублируй правила в файлах отдельных харнессов.
