# MandaGramLanding

Исходники сайта [mandagram.com](https://mandagram.com): русская и английская главные страницы, русскоязычная база знаний клиента и нативного плагинного движка, скачиваемые заголовки SDK и примеры. Сайт собран на Astro 4 и TypeScript; результат сборки — статические HTML/CSS/JS и ресурсы, без серверного API Telegram.

## Локальный запуск

Используйте Node.js 22 (как в CI) и npm. Команды выполняются из корня этого репозитория:

```bash
npm ci
npm run dev -- --host 127.0.0.1
```

Адрес разработки: `http://127.0.0.1:4321/`. Если порт занят, Astro выбирает другой: смотрите адрес в терминале. Изменения контента подхватываются автоматически. Для проверки английской страницы откройте `/en/`, документации — `/kb/`. Сервер останавливается через `Ctrl+C`.

```bash
npm run build
npm run preview -- --host 127.0.0.1
```

Сборка создаёт `dist/`; preview обслуживает именно собранные файлы, а не текущие исходники. В package.json нет отдельной команды тестов. Локальный запуск и сборка не публикуют сайт.

## Структура и владельцы контента

| Путь | Назначение |
| --- | --- |
| `src/pages/index.astro`, `src/pages/en/index.astro` | Главные страницы RU/EN |
| `src/data/team.ts` | Имя, подпись, роль, теги, ссылка Telegram и аватар участников в обеих локализациях |
| `public/assets/team/` | Аватары, доступные по `/assets/team/...`; файлы из `src/assets/` без импорта не раздаются по этому адресу |
| `src/data/features.ts`, `src/data/versions.ts` | Описания возможностей и данные версий; наличие записи не подтверждает опубликованный релиз |
| `src/data/kb.ts` | Категории, 15 статей, оглавления, соседние статьи, быстрые ссылки и поисковые данные |
| `src/pages/kb/index.astro`, `src/pages/kb/[slug].astro` | Каталог базы знаний и статически генерируемые статьи |
| `src/pages/kb/search.json.ts` | JSON-индекс из данных статей по `/kb/search.json` |
| `src/layouts/Base.astro`, `src/layouts/Kb.astro` | Общий макет, тема сайта, макет документации, навигация и оглавление |
| `src/components/KbSearch.astro`, `KbSidebar.astro`, `KbToc.astro` | Форма поиска, список статей и оглавление |
| `src/data/legal.ts`, `src/pages/{legal,pp,tos}.astro` | Юридические тексты и страницы |
| `src/styles/` | Общие стили и оформление документации |
| `public/include/`, `public/examples/` | Скачиваемый SDK и самостоятельные примеры плагинов C++, Rust, Zig и D |
| `public/sitemap.xml`, `public/robots.txt` | Статические правила индексации; новые маршруты требуют ручного обновления карты |
| `astro.config.mjs` | Адрес сайта, trailing slash, каталог ассетов `/_a/`, prefetch |
| `.github/workflows/deploy.yml`, `deploy/` | Сборка и доставка на production |

Поиск в базе знаний использует заголовок, категорию и полный текст статей, без учёта регистра и различия е/ё. Несколько слов должны встретиться в одной статье; показываются первые восемь совпадений. `/` переводит фокус в видимую строку поиска, стрелки выбирают результат, Enter открывает его, Escape закрывает список. Параметр `/kb/?q=...` запускает поиск при открытии каталога. Отсутствие совпадений и ошибка загрузки индекса показаны отдельно; морфологического стемминга нет.

Astro допускает URL со слешем и без него (`trailingSlash: 'ignore'`), чтобы файловый `/kb/search.json` одинаково работал на dev-сервере и в статической сборке. Ссылки на страницы сохраняют завершающий слеш.

Страницы статей используют центрированную сетку до 1392 px с внутренними боковыми отступами 16 px: навигация и оглавление по 216 px, статья до 880 px, промежутки между колонками по 24 px. Боковые поля симметричны, статья расположена по центру экрана. На экранах от 1100 px кнопки «Содержание» нет: раздел «На этой странице» виден рядом со статьёй. Ниже 1100 px разделы и оглавление открываются кнопками в модальных диалогах. Диалоги закрываются кнопкой, Escape, нажатием вне панели или выбором ссылки; длинный код прокручивается внутри блока, не расширяя страницу.

Прокручиваемое меню разделов на ПК имеет симметричное затенение по 32 px сверху под поиском и снизу. Верхний внутренний отступ сохраняет читаемость первого пункта до начала прокрутки.

## Как обновлять документацию движка

Источник истины — **реализация клиента MandaGram**, а не рекламный текст сайта, старый пример или комментарий SDK. Для сверки используйте соответствующий checkout [MandaGram](https://github.com/GrapeS-T/MandaGram):

- `src/native/include/mandagram_plugin.h` — порядок полей `PluginApi`, C-структуры и callback-сигнатуры; `.hpp` и `.zig` — обёртки и bindings.
- `src/main/kotlin/com/mandagram/plugin/bridge/` — FFM-мост, фактическая реализация API, TDLib JSON и Compose interop.
- `plugin/loader/`, `plugin/storage/`, `plugin/watchdog/`, `plugin/xposed/` в том же дереве — загрузка/перезагрузка, хранилище, учёт ошибок и перехват методов.
- `docs/development.md` и `docs/architecture/` клиента — карта подсистем, сетевые ограничения, пути portable-данных, UI и медиа. Возможности пользовательского интерфейса подтверждайте вызовами из UI, не только наличием enum или метода.

База знаний разделяет реализованные возможности и ограничения. Нативные плагины выполняются внутри процесса, не в песочнице; Watchdog не гарантирует восстановление после зависания или native crash. Наличие Slot API не означает, что произвольный Compose-компонент можно вставить в любую область UI. ABI не имеет поля версии или размера структуры: SDK и клиент должны соответствовать друг другу.

При изменении статей:

1. Сохраните существующий `slug`, если не делаете явную миграцию URL. Синхронизируйте `title`, категорию, `headings`, HTML `section id`, `sectionsCount`, время чтения и `prev`/`next`.
2. HTML в `content` — доверенный исходный текст, вставляемый через `set:html`, а не Markdown. Экранируйте `<`, `>` и `&` внутри примеров кода, обратные кавычки и `${...}` — внутри TypeScript template strings. Не вставляйте непроверенный пользовательский HTML.
3. Обновляйте каталожные записи и быстрые ссылки при изменении названий. Поисковый индекс строится из статей; отдельную копию `public/kb/search.json` не создавайте.
4. Синхронизируйте оба дерева публичных headers: `public/include/` и `public/examples/include/`. Порядок полей ABI и calling convention нельзя менять независимо от клиента. Примеры используют тот же SDK; удаляйте устаревшие JNI bindings, не оставляйте параллельный несовместимый API.
5. Проверьте статью на локальном стенде: оглавление, переходы, переносы кода на узком экране, доступность ссылок на заголовки и примеры. Генерация индекса сама по себе не доказывает работу интерактивного поиска.
6. Не обещайте опубликованные пакеты, поддержку форматов, безопасность или UI-функции без подтверждения. Для risky-функций описывайте последствия: PIN не шифрует файлы, Panic удаляет локальные данные, сохранённый WEB-прокси блокирует сеть до явного изменения режима.

## Добавление участника

Добавьте запись в `teamRu` и `teamEn` в `src/data/team.ts`, поместите изображение в `public/assets/team/` и укажите его публичный путь в `avatar`. `alias` подходит для Telegram-тега, `telegram` — для полной ссылки `https://t.me/...`. Не приписывайте участнику неизвестную специализацию. Пустой `tone` использует базовый стиль карточки; индивидуальные палитры находятся в `src/styles/global.css`.

Карточки команды движутся непрерывной лентой с постоянным размером и промежутками. У краёв ленты градиентная маска плавно растворяет карточки, не меняя рамку и не накладывая их друг на друга. Наведение и нажатие не меняют радиус углов. Автопрокрутка отключена при prefers-reduced-motion, ручное перетаскивание остаётся доступным.

## Публикация на mandagram.com

Production публикуется из ветки `release` через `.github/workflows/deploy.yml`. Каждый push собирает статический сайт на Node.js 22 с `npm ci`, передаёт архив по SSH и проверяет SHA на `https://mandagram.com/deployment.txt`. Ручной запуск workflow также разрешён только для `release`; `main` и `dev` не деплоятся.

Разработку ведите в рабочих ветках от `dev`, не в `main` или `release`. Коммиты — Conventional Commits с scope и перечислением изменений в body. Публикация принятого состояния — отдельная операция:

```bash
git fetch origin
git switch release
git merge --ff-only origin/main
git push origin release
```

Если fast-forward невозможен, выясните расхождение; не используйте force push.

На сервере `ssh mandagram` сайт обслуживает Caddy с автоматически обновляемым HTTPS-сертификатом. Конфигурация: `deploy/Caddyfile` → `/etc/caddy/Caddyfile`. Статика: `/srv/mandagram/releases/<SHA>`, активный сайт — атомарно переключаемая ссылка `/srv/mandagram/current`. Предыдущие версии сохраняются для ручного отката; следите за свободным местом в `releases`.

Actions использует пользователя `mandagram-deploy` без sudo. Его SSH-ключ ограничен командой `/usr/local/bin/mandagram-landing-deploy` (исходник `deploy/receive.sh`), без shell, PTY и перенаправления портов. Приватный ключ хранится только в секрете `DEPLOY_SSH_KEY`; переменные `DEPLOY_HOST` и `DEPLOY_KNOWN_HOSTS` задают адрес и проверенный ключ сервера. При смене сервера/host key обновите переменные; receiver и Caddyfile устанавливаются через административный SSH. Не коммитьте ключи и серверные секреты.

Cloudflare проксирует `mandagram.com` на origin с публичным HTTPS-сертификатом, совместимым с Full (strict). API-токен Cloudflare для деплоя не нужен. `/deployment.txt` отдаётся с `Cache-Control: no-store`, файлы `/_a/` — с immutable-кешем.
